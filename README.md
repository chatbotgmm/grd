# 갈매미맨 랜덤 디펜스 — 고도(Godot) 판

웹 판(서버 저장소 `chatbotgmm/server`의 `galmaegiman-confirmed/public/defense`)을 고도 4.7로 옮기는 중인 프로젝트예요. 한 프로젝트에서 웹·안드로이드·iOS로 내보내는 것이 목표예요.

## 저장소 나눔
- 이 저장소(`chatbotgmm/grd`): 고도 판에 필요한 것만 — 코드·장면·데이터 JSON·글꼴·쓰는 그림(`assets/art`, 134개).
- 웹 판 규칙(`engine.js`)·원본 그림은 서버 저장소에 있어요. 수치를 다시 뽑거나(`tools/export_data.mjs`) 그림을 다시 복사하거나(`tools/sync_art.mjs`) 비교 시험(`tools/compare.sh`)을 할 때만 서버 저장소가 필요해요.
  - 서버 저장소를 이 저장소 **옆에** 받아 두면(`../server`) 자동으로 찾아요. 다른 곳이면 `GMM_WEB_DEFENSE=<서버 저장소>/galmaegiman-confirmed/public/defense`.
- 게임을 열어 보기만 할 때는 서버 저장소가 필요 없어요.

## 지금 단계: 2단계-1(게임 화면 기본) 완료
- **게임 화면**(`scenes/game.tscn`, 처음 뜨는 화면): 웹 판 가로 배치 그대로 — 왼쪽 판 + 위 정보 줄, 오른쪽 이번 웨이브 피해 순위 + 아래 메뉴.
  - 처음 화면에서 난이도를 고르면 시작. 갈매미·적 그림, 체력 칸, 스턴 별, 겹친 수, 사거리, 공격 동작·범위·연쇄·고유 기술(간단한 선·고리)·보스 피해 숫자.
  - 위습 칸 누르면 소환(1~5 키도), 갈매미 누르면 고르기 + 끌어서 옮기기(고른 무리는 함께), 빈 곳을 끌면 여러 마리 고르기.
  - 갈매미 하나 고르면: 설명·유틸 칩·리롤·「이 갈매미로 만들 수 있는 것」(바로 조합)·모으기·위치 고정·창고·탐사·판매. 여러 마리면 탐사·창고·고정.
  - 일시정지(Ⅱ·스페이스)·속도(×1·×2·×3)·게임 끝 창(다시 하기).
  - 아직 없음(다음 단계): 조합법 창·정보창(재료 나무)·강화·외부탐사·더보기 창, 공격 연출 그림, 소리, 이어하기, 같이하기, 꾸미기, 보스 경고.
- `scripts/engine/engine.gd`: 웹 판 `engine.js`(규칙)를 GDScript로 옮긴 것(1단계). 화면과 분리되어 있어요.
- `data/game_data.json`: 유닛·조합법·밸런스 수치. **웹 판 `engine.js`에서 자동으로 뽑아요**(아래). 수치는 웹 판 한 곳에서만 고쳐요.
- `scenes/preview.tscn`: 1단계 엔진 미리보기(도형). 편집기에서 이 장면을 열고 F6으로 실행.

## 받아서 열어 보기
1. 고도 4.7 이상(표준판, .NET 아님)을 받아요: https://godotengine.org/download
2. 고도 프로젝트 관리자에서 「가져오기」 → 이 저장소의 `project.godot`을 골라요.
3. 처음 열 때 글꼴·그림을 가져오느라 잠깐 걸려요. ▶(F5)를 누르면 게임 화면이 떠요.

## 웹 판과 결과가 같은지 시험
같은 시드·같은 행동이면 웹 판과 **비트 단위까지 같은 결과**가 나와야 해요. 5초마다 판 상태(웨이브·새우·처치·적 체력 합·갈매미 목록·난수 상태 등)를 비교해요.

```bash
GODOT=/고도/실행/파일 bash tools/compare.sh
```
(이 저장소 맨 위 폴더에서. Node.js와 옆에 받은 서버 저장소가 필요해요.)

시험 판: 달인·상급·장인 초반, 입문·중급 60웨이브 완주(외부탐사 13장), 고유 기술 8종 모두 · 위습 찾기 · 판매·리롤·창고·옮기기·모으기·고정·불러오기, 900초에 저장→되살리기.

### 웹 판과 같게 맞추려고 지킨 것
- 위치는 `Vector2`(32비트 실수)가 아니라 64비트 실수 `{x, y}`로 계산(Vector2로 하면 좌표가 조금씩 달라져 결과가 갈라졌음).
- `Math.round`(.5 올림), `Math.hypot`(V8 방식), 32비트 난수(mulberry32), 안정 정렬, JS 객체 키 순서를 그대로 흉내 냄.
- 사전(Dictionary)의 `==`는 내용 비교라서, 같은 적인지 볼 때는 `is_same()`을 씀.
- 고도 JSON 읽기는 소수의 마지막 자리를 틀릴 수 있어서, 비교 기록의 실수는 64비트 그대로(16진수) 주고받음.

## 밸런스 수치를 바꿨을 때
웹 판 `public/defense/engine.js`(서버 저장소)를 고친 뒤 이 저장소에서:
```bash
node tools/export_data.mjs
```
그림이 바뀌었으면 `node tools/sync_art.mjs`.
규칙(계산 방식)을 바꿨다면 `scripts/engine/engine.gd`도 같이 고치고 위 비교 시험을 돌려요.

## 화면 캡처(디자인 검토용)·입력 시험
```bash
xvfb-run -a godot --path . --rendering-driver opengl3 --resolution 915x412 --script res://scripts/test/shot.gd -- 결과.png game unit
```
상황: `title` · `play` · `unit` · `group` · `boss` · `pause` · `over` (장면 `preview`도 됨)
```bash
xvfb-run -a godot --path . --rendering-driver opengl3 --resolution 915x412 --script res://scripts/test/input_test.gd
```
실제 누르기·끌기 사건으로 시작·위습 소환·끌어 옮기기·여러 마리 고르기·해제·일시정지를 확인해요.

## 알아 둘 점
- 속도: 고도 판 엔진은 같은 계산을 웹 판(Node)보다 약 14배 느리게 해요(이 작업 환경 기준, 고유 기술 갈매미가 많은 60웨이브 판: 웹 5.7초 · 고도 82.7초 = 초당 약 725걸음). 게임은 초당 20걸음(×1)~160걸음(×8)이 필요해서 PC에서는 넉넉하지만, 휴대폰에서 ×8은 확인이 필요해요.
- 데이터 JSON을 내보낼 때 넣으려면 내보내기 설정의 「리소스가 아닌 파일」에 `data/*.json`을 넣어야 해요(내보내기 설정을 만들 때 함께 할 예정).
- 글꼴: `assets/fonts/workbench-noto-regular.otf`(웹 판과 같은 글꼴, SIL 오픈 폰트 라이선스 — `OFL-workbench.txt`).
